# Research docket — "The Instrument"

`prosodia plan` feeds every `*.md` in this directory straight into the Planner, so the outline is
built from verified material rather than from open-web research at plan time. This directory is
gitignored: it is scratch, and the distilled result lives in the tracked `plan/outline.md`.

**`07_operative_text.md` outranks every other file here.** It is the Regulation itself, verbatim
from the EUR-Lex consolidated text (CELEX 02024R1689-20260727, as amended by Regulation (EU)
2026/1744), extracted on 2026-09-13 with a completeness check on every article. Everything else in
this directory is secondary — useful for context, cases and critique, but **not quotable**. Where
07 and another file disagree, 07 is right.

What this series needs before planning, at minimum:

- **The Act itself.** Regulation (EU) 2024/1689, consolidated. Recitals 1-30 for the reasoning;
  Arts. 1-6 (scope, definitions, classification); Art. 5 (prohibitions); Chapter III (high-risk);
  Chapter V (GPAI); Chapter VII (governance); Chapter XII (penalties); Annex III.
- **The drafting history**, enough to answer "why this rule and not another" — what the
  product-safety route was chosen over, and what was traded away for it.
- **Real, documented controversies** to open episodes on: named systems, named deployers, dates,
  outcomes. The persona forbids invented cases, so an episode without one cannot be written as
  designed.
- **The standing critiques**, with who holds them: the product-safety framing, the
  standardisation deficit, the fundamental-rights-impact gap.
- **What the machine actually does** for each system discussed — operational descriptions from
  the technical literature, not vendor copy. The persona's signature beat needs this.
- **Date stamps** on everything contingent: thresholds, deadlines, codes of practice, guidance.

Flag explicitly anything the docket could NOT establish; the Planner is told to web-search only
for gaps the docket names.
